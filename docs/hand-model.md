# 3点構成で、ロストした手の位置を補完する

HMDと左右のコントローラーだけを使い、ロストしたコントローラーの位置を短時間補完する。
設定の **「遮蔽中の手を肩に追従させる」** で切り替える。既定オフ。
腰の身体モデルとは独立しており、腰・足トラッカーや仮想デバイスの生成は必要ない。

## 使い方

1. 全体の補正と、対象の手のデバイス別補正をオンにする。
2. 設定で「遮蔽中の手を肩に追従させる」をオンにする。
3. 同じ欄の「基準HMD」を指定する。腰の補完とこの指定を共有する。未指定で HMD が1台だけなら、その HMD を自動で使う（「（自動：接続中の HMD）」と表示）。HMD が2台以上あるときは指定が必要。
4. HMDと手を正常に追跡できる状態にする。0.1秒以上の正常な観測で準備が整う。
5. 手を短時間だけ遮り、体を少し移動させて、オフの場合の位置保持と比較する。

左右は SteamVR の `Prop_ControllerRoleHint_Int32` を使う。
Controller クラスで LeftHand / RightHand と判別できるデバイスにだけ適用する。
役割不明のコントローラーや GenericTracker を位置・番号・シリアルの順序から手だと推定する処理はない。
基準HMDの補正を有効にする必要はない。基準HMDと反対手は補正前の生のposeを参照する。
補正を除外した反対手も参照でき、補完した手を別の手の基準にする循環はない。

## 何を推定するか

この版は **肩に対する最後の手位置を保つ方式に、腕の到達距離の制約を加えたもの**。
見えない手の自由な動きや、肘・手首の関節姿勢を逆算するものではない。

1. HMD の `driverFromHead` の位置・回転も適用して頭の位置を得る。
2. 頭から首へのオフセットは腰モデルと共通の `bodyNeckDownCm` / `bodyNeckBackCm` を使う。
3. 首から左右の肩を推定する。肩は首から10cm下、左右に肩幅の半分だけ離れた支点として近似する。
4. ロスト開始時の頭の水平な向きで肩の配置を定め、肩に対する直前の出力手位置を保存する。
5. 遮蔽中は首・肩の平行移動にその位置を追従させる。頭を回すたびに胴体と手を回す処理は入れない。

world 座標での概略:

```
shoulder_offset = yaw_at_loss * (side * shoulder_width / 2, -0.10, 0)
hand_offset = last_output_hand - (neck_at_loss + shoulder_offset)
estimated_hand = current_neck + shoulder_offset + hand_offset
```

腕の最大到達距離は肩からコントローラー原点までの距離で、手の分も含む。
正常な実測がこの距離を超えていても実測は変更しない。ロスト開始時に範囲外なら、その回は位置保持を使う。
出力の移動速度を制限した結果、腕の到達距離を超える場合は範囲内へ制約する。
到達距離と滑らかさを両立できない場合は、その時点の出力位置で保持する。

### 信頼度が足りない場合

- 正常なHMDの観測が100msより古ければ推定しない。
- 直前の正常な手の観測が100ms以内にない場合、その回の推定を開始しない。
- 頭の水平な向きを取れないほど上や下を向いている場合も推定しない。
- HMD由来の首位置が1回で15cmを超えて移動したら、その回の推定を中止する。
- 反対手がロスト開始時も現在も正常に見えている場合、首が15cm以上動いた一方で反対手が5cm未満しか動いていなければ、頭だけの前屈等との区別が難しいため、その回の追従を中止する。
- 反対手を見失っていてもHMDを基準に推定できる。両手ロストも同じ時間制限を使う。
- 移動は最大1.5m/s・1回5cmまで。推定位置が現在の保持位置から35cmを超えて離れていたら採用しない。
- 推定を続ける時間は既定3秒（ロスト開始から数える。更新が単に止まった場合は最後の更新から）。手の回転は使わないので、Lighthouse が 2 秒で送信をやめた後も続く。時間切れでは最後の出力位置を保持し、光学復帰を待つ。
- 切断・手の寸法や推定時間の変更・トグル変更・基準HMDの変更は準備状態を破棄する。ロスト中にオンへ切り替えても、その回の推定は開始しない。

これらは安全側に倒すためのヒューリスティックで、実際に胴体が動いたことの証明ではない。
HMD自体が頭と一緒に移動するため、頭だけの傾きと全身の移動を完全には分離できない。

### 腕モデル（手の回転で位置も動かす）

手の回転が届いている間（Lighthouse の範囲外の回転、または [IMU](imu.md)）は、肩追従に加えて回転で手の位置を動かす。

- 見えている間に、コントローラーから見た肩の方向（コントローラー自身の軸で、持ち方による）を平均して覚える。
- ロスト開始時、その方向に前腕の長さ（`forearm`、26cm）だけ離れた点を肘とする。肘は肩についていく。
- 以後、コントローラーがロスト開始時から回った分の `armFollow`（既定75%）だけ、手を肘の周りに回す。回転が届かなくなったら最後の曲がり具合を保つ（肩追従の位置へ跳ね戻らない）。
- 回転が届いている間は推定を最長30秒まで続ける（回転がなければ従来どおり `maxPrediction`）。
- 首（肩）の移動のうち最初の10cm（`followDeadzone`）は追従しない。見回す・少し傾くといった頭だけの動きで、止まっている手まで動かさないため。
- 腕を伸ばす・縮めるなど、回転を伴わない移動は分からない。

`handArmFollowPct`（0〜100、既定75）で強さを変えられる。0 で従来の肩追従だけ。

録画での比較（`tools/analysis/compare_hand_models.py`、見えていた区間を1秒・3秒だけ擬似的に隠し、本物の位置からのずれの平均 / 95パーセンタイル、cm）:

| 録画 | 手 | 遮蔽 | その場で保持 | 肩追従 | 腕モデル75% | 腕モデル75%＋不感帯10cm（既定） |
|---|---|---|---|---|---|---|
| `20261024-170855_body`（体を動かす） | 右 | 3秒 | 16.8 / 70.6 | 12.7 / 53.1 | 10.9 / 40.8 | 11.7 / 43.1 |
| | 左 | 3秒 | 16.1 / 77.8 | 12.6 / 58.8 | 10.3 / 36.4 | 9.9 / 33.8 |
| `20261025-150420_overlay`（ほぼ静止） | 右 | 3秒 | 4.0 / 14.3 | 6.6 / 14.8 | 7.4 / 18.1 | 5.4 / 18.8 |
| | 左 | 3秒 | 1.9 / 10.8 | 4.5 / 15.1 | 3.9 / 12.1 | 1.7 / 7.6 |

擬似遮蔽は実際の回転を残すので、IMU の回転のずれ（実機で数秒あたり数度）は含まない。

### 回転と復帰

位置の推定にはコントローラーの回転を使わない。手首だけを回しても腕全体が回るとは仮定しない。
ロスト中も連続したpose回転が届けば、既存の腰補完と同じ連続性チェックを通して回転へ適用する。
入力が止まった場合は最後の回転で固定し、HMDが新鮮なら時間制限内だけ位置の追従を続ける。
生IMUの取得や、加速度の二重積分は行わない。

復帰は既存の HOLD → PROBATION → BLEND を使う。
手の補完が有効な場合は、復帰待ち中の位置・回転の大きな段差で待ち時間をやり直し、
位置とworld回転を補間して実測へ戻す。正常時は身体モデルによる出力変更を行わない。
ジッター補正・通常時の段差補正は従来どおり独立して動作する。

## 設定・診断

管理画面での変更は即時反映し、既存の vrsettings に保存する。CLI の `set` は実行中だけの変更。

| キー | 既定 | 範囲・意味 |
|---|---:|---|
| `handEnabled` | `false` | 手の補完の切り替え |
| `handShoulderWidthCm` | 36 | 20～60cm、左右の肩の支点の間隔 |
| `handArmReachCm` | 70 | 30～120cm、肩からコントローラーまでの最大距離 |
| `handMaxPredictionMs` | 1000 | 100～3000ms、ロスト後に推定を続ける時間 |
| `bodyHmdSerial` | 空 | 腰モデルと共通の基準HMD（空なら、HMD が1台だけのときその HMD） |

寸法の既定値は汎用の仮の値で、ユーザーの実寸の測定値ではない。必要に応じて調整する。

```
ots-cli set bodyHmdSerial <HMDのシリアル>
ots-cli set handEnabled true
ots-cli devices
ots-cli set handEnabled false
```

`devices` には `handSide`（左=-1、右=1、不明=0）、`handReady`、`handActive` を追加した。
役割・接続デバイスの情報はバックグラウンドで約1秒ごとに再確認する。
記録には生pose・出力pose・設定に加えて、Note の `hand_model` イベントとして推定・保持・待機の状態変更を残す。
補完に追加の録画形式や外部サービスは必要ない。

## リプレイ・検証

対象録画の DeviceInfo でHMDの番号と左右のroleを確認する。

```powershell
# 実際に起きたロストを、手の補完をオンにして再評価する。
build\tools\ots-replay\Release\ots-replay.exe input.otsrec -o hand.otsrec `
  --reference-hmd 0 --set handEnabled=1

# 例: 左手=8、右手=6。両方を10～11秒に擬似遮蔽する。
build\tools\ots-replay\Release\ots-replay.exe input.otsrec -o masked.otsrec `
  --reference-hmd 0 --set handEnabled=1 --mask-device 8 --mask-device 6 --mask 10:11

# 正常な区間に1秒の擬似遮蔽を作り、位置保持・HMD平行移動・肩追従を比較する。
python tools\analysis\eval_body_model.py input.otsrec `
  --hand <コントローラーのシリアル> --hmd <HMDのシリアル> --out build\hand-eval
```

リプレイの調整キーは `handShoulderWidth` / `handArmReach`（m）、`handMaxPrediction`（秒）。
ライブの設定キーの cm / ms とは単位が異なる。
録画内の設定変更を自動適用するものではなく、指定した一定の設定で再評価するツール。
録画途中のrole変更も再現せず、DeviceInfoから得た役割で処理する。
