# Phase 2: ダッシュボード マネージャー（仕様）

## 目的

SteamVR のダッシュボードとデスクトップのウィンドウから、次のことを GUI で行えるようにする。

- 補正（Phase 1 のフィルタ）のオン・オフと、デバイスごとの切り替え
- 補正が効いている様子（生の値と補正後の値）をリアルタイムのグラフで確認
- BS と各デバイスの位置をマップ（上から / 横から / 3D）で確認
- 補正のパラメータ（ジッター補正を含む）の調整と保存
- Lighthouse とドライバ、補正の状態変化、操作のログの確認

## 構成

```
SteamVR ダッシュボード ─┐
デスクトップのウィンドウ ┴ OTS マネージャー（tools/ots-overlay、SteamVR と一緒に自動起動）
     ├ デバイス / BS / マップ … OpenVR クライアント API（IVRSystem, IVRChaperone）
     └ 補正 / グラフ / ログ   … ドライバの制御パイプ（\\.\pipe\OpenVR-TrackingStabilizer）
```

| 要素 | 内容 |
|---|---|
| オーバーレイアプリ | `VRApplication_Overlay` として起動し、`CreateDashboardOverlay` でダッシュボードにタブを追加する。`SetOverlayTexture` で D3D11 のテクスチャを渡す |
| UI | [RmlUi](https://github.com/mikke89/RmlUi)（HTML/CSS に近い C++ の UI ライブラリ、MIT）。画面は `ui/app.rml`、見た目は `ui/app.rcss`、アイコンは Lucide の SVG（lunasvg で描画）。ブラウザ（Chromium）は使わない |
| 描画 | レイアウトは 1120×700（単位は dp）。テクスチャ 1 枚に描き、VR とデスクトップのウィンドウの両方に出す。解像度はデスクトップのウィンドウの実ピクセル数に合わせる（サイズ変更が落ち着いてから）。VR のために横 1600 px 以上を保ち、ウィンドウを閉じているときは 1600×1000。ウィンドウの初期サイズは作業領域の半分（最大で 1 dp = 画面の 1 論理ピクセル）。どちらにも表示されていないときは描画しない。表示中は約 30fps |
| 入力 | オーバーレイのマウスイベント（レーザーポインタ）とデスクトップのマウスを、同じ UI に渡す |
| 起動 | 初回だけ手動で `ots-overlay.exe` を起動すると、自分のマニフェストを SteamVR に登録し、自動起動を有効にする |
| ドライバとの通信 | 制御パイプ。別スレッドで、表示中は 100ms ごと、非表示中は 250ms ごとに問い合わせる |
| 言語・テーマ | 英語（既定）と日本語。テーマは ダーク・ブルー（既定）/ クリムゾン / ダーク・パープル / ライト。切り替えると画面を読み直す |
| 保存先 | 表示の設定は `%LOCALAPPDATA%\OpenVR-TrackingStabilizer\overlay.json`、補正の設定は `steamvr.vrsettings` の `driver_trackingstabilizer` |
| 文字 | Windows のフォント（Noto Sans JP → Yu Gothic → Meiryo、等幅は Consolas） |

`ots-overlay --screenshot <dir>` で、全画面をデモデータで PNG に書き出せる（`scripts/overlay-shots.ps1`）。

## 画面

画面は「補正」「デバイス」「設定」の 3 つ。用語は「補正」に統一し、ロスト中に位置を止めている状態は「補正中」と呼ぶ。

### 補正（メイン）

- 上部のバー: 補正のオン・オフのスイッチ、補正の対象の台数、現在のデバイス数、補正中の台数、このセッションの総補正回数。
- グラフ（直近 20 秒）: デバイスごとに 1 行。各行に「補正後」（実線）と「生の値」（破線）を、そのデバイスの平均位置からの距離（cm）で描く。どの方向に飛んでも出る。2 本の間を塗り、行の上端の細い帯で「補正中」「未補正」の区間を示す。行の左に名前（モデル名とシリアル）、状態、ずれ、補正のスイッチ。
- マップ: 上から / 横から / 3D（ドラッグで回転、ホイールで拡大）。補正中のデバイスは輪で囲み、生の位置を破線の丸で示す。
- ログ: 新しい順。「絞り込み」ボタンで種類（Lighthouse ドライバのログ / Stabilizer ドライバのログ / 補正の状態の変化 / この画面での操作）を選ぶ。

### デバイス

| 列 | 内容 | 取得元 |
|---|---|---|
| デバイス | モデル名とシリアル、種類のアイコン（色で状態） | `Prop_ModelNumber_String`, `Prop_SerialNumber_String` |
| 補正 | デバイスごとのスイッチ。HMD は設定の「HMD も補正する」がオンのときだけ切り替えられる | パイプ `set filterIncludeSerials` / `filterExcludeSerials` |
| 電池 | 残量（20% 未満は赤、40% 未満は橙） | `Prop_DeviceBatteryPercentage_Float` |
| 状態 | 追跡中 / 補正中（何秒ロストしているか）/ 復帰を確認中 / 復帰中 / ロスト（未補正） | パイプ `devices`、追跡状態 |
| 補正回数 | このセッションで補正した回数 | パイプ `devices` |

ベースステーション: シリアル・チャンネル、高さ、下向きの傾き、状態（SteamVR が認識しているか）。

### 設定

- 補正するデバイスを選ぶ（デバイス画面へ）、「HMD も補正する」（VR 酔いの注意書き付き）。
- パラメータ（すべて即時反映、`steamvr.vrsettings` に保存）:

| グループ | 名前（日本語 UI） | キー | 既定 |
|---|---|---|---|
| 小刻みな揺れ | ジッター補正 | `smoothing`（0–100 %） | 0 |
| トラッキングロスト時の復帰 | 復帰を待つ時間（リセット後） | `probationMs` | 400 |
| | 復帰を待つ時間（短いロスト） | `shortProbationMs` | 100 |
| | 元の位置へ戻る時間 | `blendMs` | 200 |
| ワープ（瞬間移動） | ワープとみなす距離 | `stepLimitCm` | 4.5 |
| | ワープをならす時間 | `stepBlendMs` | 150 |

- レコーディング（デバッグ用）: 生の値と補正後の位置、Lighthouse のログ、補正の動作を `.otsrec` に保存。マーカー。
- 言語、カラーテーマ、表示（デスクトップのウィンドウ、マップの既定の表示）、このアプリについて（制作者、GitHub）。

## ドライバ側の追加

| 追加 | 内容 |
|---|---|
| ログのリングバッファ | 直近 2000 件 `{seq, t, kind, text}`。kind = `driver`（フックで受けた他ドライバのログ）/ `ots`（自分のログ）/ `filter`（状態遷移） |
| パイプ `log <seq>` | `seq` より新しいエントリを JSON で返す（1 回最大 500 件） |
| パイプ `trace <since>` | デバイスごとの生の位置と補正後の位置（ワールド座標、mm）と状態を 30Hz で、直近 25 秒ぶん返す。問い合わせから 5 秒間だけ記録するので、UI を閉じていれば負荷はない |
| デバイスごとの切り替え | `filterIncludeSerials` / `filterExcludeSerials`（カンマ区切り、`-` は空）。コントローラーとトラッカーは除外されていなければ補正、HMD は `filterHmd` かつ含める指定のときだけ補正。切り替えの間も補正中のデバイスは保持を続ける |
| ジッター補正 | `smoothing`（0–100 %）。位置と回転に One Euro フィルタ（動きが速いほど遅れが小さい）。速さはドライバが報告する速度で判定し、報告する速度・角速度も同じく平滑化する（SteamVR はこの速度で約 40ms 先を予測して描くため、生のままだと揺れが戻る）。0 なら出力はそのまま |

## 安全面

- HMD の補正は既定でオフ。設定でオプトインし、さらにデバイスごとにオンにしたときだけ。
- オーバーレイが落ちても SteamVR とドライバには影響しない（別プロセス）。

## Phase 2 でやらないこと

- トラッカー・コントローラー・BS の電源操作（一度実装したが外した。OyasumiVR などの専用ツールに任せる。BS 2.0 は Bluetooth で 1 つのアプリが独占して接続するため、併用するとどちらかが操作できない）
- ユニバース（BS 配置）の編集や再キャリブレーション
